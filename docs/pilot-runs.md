# Pilot runs: what was run, what it cost, what it found, what changed because of it

Clock times stay only where a log, a recording or a commit shows them (runs 0, 1, 22 and 54–56: commit times; runs
7–10, 12, 20 and 21: logs); the other rows carry the date only. Times first written on runs 2–6, 11 and 13–19 were estimates,
not readings, and were removed.

Every row comes from a command's output at the time, or from the record files named in it.
Prices: `muse-spark-1.3` $1.25 per million input tokens and $4.25 per million output; SAM 3.1 $0.20 per 1k video
frames (50-frame minimum) and $2.50 per 1k images (`docs/api.md`); `muse-wonder-1.0` (runs 42–46 and 54–56) $4.00 per million
input tokens, $0.20 for the cached ones, and $20.00 per million output. Phone runs used the `Small_Phone`
emulator (Android API 36, 720×1280) on a Mac; the arena checks ran offline. Times are Dubai unless marked. Single-step
phone runs are a **proxy**, not GhostEI's multi-step harness, so their rates are not comparable to the paper's.

## Findings that changed the design, in one line each
1. **Back does not dismiss an overlay** (runs 2, 3): the gate's remedy is to stop and report the owner, which costs the
   task its availability; the README says so.
2. **The accessibility tree exposes the attacker's buttons with their package and bounds** (run 4), so "hijacked" can be
   measured geometrically and the owner under a tap point read off the tree, no vision needed.
3. **Muse Spark's raw tap coordinates are unreliable at 720×1280** (runs 6, 7, 10): y 59–161 px high when it names a
   button, 0 of 32 hits on the named element in the attack run, 4 of 132 taps off the screen. "Fooled" (the named
   target) is the hijack number; raw "harm" is a grounding artefact. Any real agent framework resolves the named
   element from the tree, which is why the gate reads the owner from the tree too.
4. **Telling the model the window's owner removes the intent hijack** (runs 2, 9: 4 of 20 → 0 of 20; 5 of 33 → 0 of 33),
   and the owner gate still blocks every tap that lands on the attacker's window (runs 7, 9). The false-block price was
   1 of 27 (run 8) and 4 of 27 (run 10, all off-screen points).
5. **Single-step decisions vary between runs** (runs 1 and 7 disagree on which ids were fooled): the final run was
   made at `temperature: 0`, which API 1 measured as honoured.
6. **Muse Spark's defaults on the Responses API are `temperature: 1.0` and `reasoning.effort: "high"`** (echoed in all
   33 responses of run 10, which sent neither). So every pilot run (runs 7–10) sampled at temperature 1 with high
   reasoning; the final run sends `temperature: 0` (echoed `0.0` in runs 11, 12) and keeps the default effort.
7. **The click event names what the tap really reached** (run 13): `Cancel` when the button was hit, the body text when
   the body was. A click check must therefore compare it with the resolved tree node, not the model's words.
8. **SAM 3.1 wants colour-plus-"object" phrases and bills 50 frames per request** (API 2–4): one call per block with
   "colored object" tracks every element at 128 px, and a 49-step block costs the same as a 30-step one, but does not fit the arena (run 30).
9. **A one-action-dead body plus the agent's own probe can make a "feasible" case unreachable** (run 22): the arena must
   keep the goal reachable from wherever the probe leaves the element, or the eval scores the arena, not the gate.
10. **A wall rule that drops steps hides an element the gate must see** (runs 23, 26): an element pressed to a wall
    still moves along it, and the clamp is part of what an action does there. Kept and clamped, the steps cost
    nothing measurable: blocked made 0 false acts in 1,000 seeds before and after, and the block count went from
    4,926 to 4,908 on seeds 200–399.
11. **A stored Wonder response can be lost, so the conversation is sent as input items** (runs 43, 44): a
    `previous_response_id` set seconds after its response was created got `400 referenced response not found or
    expired`, a retry did not recover it, and the whole transcript as items was accepted. The reasoning item is left
    out; it holds no text, and the input count was 6 tokens higher with it.
12. **Wonder's reasoning needs room** (runs 42, 45): at 400 output tokens 6 of 11 replies were cut off; at 2,000 none of
    17 was, the longest using 763. In the kill test 32 of 1,207 replies were cut off at 2,000: 31 of no-gate+SAM's 426,
    1 of gated+SAM's 376, none of gated+colour's 405 (runs 54–57; `results/kill-cache/count.py`).
13. **Neither Muse Wonder at `temperature: 0` nor SAM 3.1 reliably repeats itself** (run 57): of the 178 requests
    that two or more conditions sent alike (for SAM, the same frames), 175 got replies that differ byte for byte; in
    content, 118 of the 121 SAM replies and 51 of the 57 Muse replies differ (`results/kill-cache/count.py`). So the
    three conditions' caches cannot share one folder, and each is kept as its own archive. The kill test's numbers are one
    sample of each service: a replay of an archive reproduces them, a second paid run would not be expected to.
